## 3. Precedence Model

The dynamic form engine executes conditional field rules according to the strict precedence ladder:
$$\text{NOT\_APPLICABLE} > \text{SYSTEM\_MANAGED} > \text{CONDITIONALLY\_REQUIRED} > \text{REQUIRED} > \text{OPTIONAL}$$

- If a field is `NOT_APPLICABLE` to the selected subcategory, it is immediately purged and not rendered.
- If a trigger is active (`Trigger == True`), the dependent field upgrades to `REQUIRED`.
- If a trigger is deactivated (`Trigger == False`), incompatible fields are automatically purged from `structured_metadata` during sanitization.
