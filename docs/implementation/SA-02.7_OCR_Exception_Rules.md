# SA-02.7 — OCR Exception Rules & Ambiguity Resolution

## 1. Document Purpose & Foundational Principles

This document defines the deterministic rules and protocols governing every OCR and text extraction exception, ambiguity, mismatch, manual override, or failure state within the AchieveNest Student Award & Portfolio Flow.

### The Inviolable Operational Principles
1. **The Student Authority Principle**: The student possesses absolute authority to review, correct, complete, or replace any extracted suggestion before submission.
2. **The Non-Blocking Extraction Principle**: OCR extraction failure **never** prevents manual form completion or valid final submission.
3. **The Non-Verification Principle**: High OCR confidence or successful extraction **never** marks an achievement record as verified. Verification is strictly reserved for authorized evaluators.
4. **The Zero-Guessing Principle**: When document cues are ambiguous, incomplete, or unrecognized, the system surfaces the ambiguity explicitly rather than silently guessing values.
5. **The Manual Input Immutability Principle**: Student-entered values are protected against silent overwriting (`DO_NOT_OVERWRITE_MANUAL_VALUE`).

## 3. Exception-to-Submission Handoff Classification

Every exception state is strictly classified into its editing versus submission impact:

| Exception Code | Can Continue Form Editing? | Can Submit If Resolved Manually? | Final Blocking Rule (for SA-02.8) |
|---|---|---|---|
| **`EX-01` (No Value)** | **YES** | **YES** | Blocked only if field is `REQUIRED` under SA-02.2 and student leaves it blank. |
| **`EX-02` / `EX-03` (Ambiguity)** | **YES** | **YES** | Blocked only if student fails to select a valid date/option for a required field. |
| **`EX-04` / `EX-05` (No Match)** | **YES** | **YES** | Blocked only if student fails to select a valid canonical option for a required field. |
| **`EX-06` (Partial Value)** | **YES** | **YES** | Blocked only if field validation fails (e.g. date missing month/day). |
| **`EX-07` (Invalid Value)** | **YES** | **YES** | Blocked only if invalid value remains uncorrected. |
| **`EX-08` (Manual Override)** | **YES** | **YES** | **ALLOWED**. Manual input is authoritative. |
| **`EX-09` (Cleared Value)** | **YES** | **YES** | Blocked only if cleared field was `REQUIRED`. |
| **`EX-10` / `EX-11` (OCR Failure)** | **YES** | **YES** | **ALLOWED**. OCR failure never blocks submission if student completes required fields. |
| **`EX-12` (Manual Preserved)** | **YES** | **YES** | **ALLOWED**. |
| **`EX-13` (Multi-File Conflict)** | **YES** | **YES** | **ALLOWED**. |
| **`EX-14` (High Confidence)** | **YES** | **YES** | **ALLOWED**. Transitions record to `pending_verification`. |
| **`EX-15` (Protected Tampering)** | **YES** | **YES** | **ALLOWED**. Backend strips protected keys and processes clean submission. |
