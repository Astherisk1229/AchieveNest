# SA-02.7 — Ambiguity Resolution Matrix

## 1. Document Purpose
This document specifies deterministic resolution protocols when document extraction encounters multiple plausible values, ambiguous calendar dates, conflicting numeric quantities, multi-option controlled vocabulary hits, or conflicting multi-file results.

## 3. Date Ambiguity Protocols

When parsing dates from OCR text layers:
1. **Calendar Validation**: Dates are checked via `isValidCalendarDate(year, month, day)`. Impossible dates (e.g. `2026-02-30`, `2026-04-31`) are rejected as `INVALID_VALUE`.
2. **Ambiguous Delimiters (`MM/DD/YYYY` vs `DD/MM/YYYY`)**:
   - If first token $> 12$, it is deterministically parsed as Day (`DD/MM/YYYY`).
   - If second token $> 12$, it is deterministically parsed as Day (`MM/DD/YYYY`).
   - If both tokens $\le 12$ and format is ambiguous, the system prompts the student to confirm rather than silently guessing the month/day inversion.
3. **Multi-Date Deduplication**: All dates found are normalized to ISO `YYYY-MM-DD` and deduplicated into a Set before presentation.

---

## 4. Multi-Evidence File Conflict Protocol

When an achievement has multiple uploaded documents:
1. **Primary Source**: Initial extraction suggestions are generated exclusively from the **first eligible uploaded file** (File index 0).
2. **Conflicting Content across Files**:
   - The engine **never** silently combines contradictory fields from disparate files.
   - If the student uploads File A (Regional level) and File B (National level), the form retains File A suggestions until the student either manually changes the field or clicks "Extract from this file" on File B.
   - The student's manual input always supersedes any file suggestions.
