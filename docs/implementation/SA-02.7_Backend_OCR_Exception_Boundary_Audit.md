# SA-02.7 — Backend OCR Exception Boundary Audit

## 1. Document Purpose
This audit analyzes backend security boundaries, persistence rules, and error recovery in CodeIgniter 4 controllers and services during OCR exception states.

---

## 2. Backend Exception Boundary Matrix

| Exception Scenario | Client Submission Behavior | Backend Ingestion & Protection Protocol | Persistence State | Audit Status |
|---|---|---|---|---|
| **OCR Fails / Crashes** | Student enters all required fields manually and clicks "Submit". | Backend validates presence of mandatory base and structured fields (`StudentAchievementValidationService`); verifies evidence attachment exists in storage. | Record created with status `submitted` (valid and awaiting evaluation). | **COMPLIANT** |
| **Tampered Status (`status: "verified"`)** | Malicious client sends status override due to high OCR confidence. | Backend controller ignores/overrides client-supplied status; forces status to `draft` or `submitted`. | Record created with status `submitted`; `verified_by` remains `NULL`. | **COMPLIANT** |
| **Injected Points (`score: 50.00`)** | Client attempts to claim award points in payload. | `FORBIDDEN_METADATA_KEYS` security filter strips `score`, `points`, `calculated_points` before persistence. | Score points remain `0.00` until backend evaluation runs. | **COMPLIANT** |
| **Corrupted File Attachment** | Client uploads damaged or spoofed binary. | `SecurityController` (Frontend) and `LocalEvidenceStorageService` (Backend) validate magic bytes; rejects corrupted upload before processing. | Upload rejected with HTTP 422; existing record unaffected. | **COMPLIANT** |
| **Unmatched / Invalid Dropdown Value** | Client submits invalid controlled key (e.g. `event_level: "galaxy"`). | Backend validation rules reject payload; returns HTTP 422 error list pointing to invalid field. | Submission blocked until student selects valid canonical option. | **COMPLIANT** |
| **Draft Persistence with Incomplete Fields** | Student saves draft with partial OCR values. | Draft persistence endpoint accepts partial fields; marks record as `draft`. | Stored as `draft`; cannot participate in evaluation until final submission. | **COMPLIANT** |

---

## 3. Storage Integrity & Decoupling Rule

1. **Evidence File Safety**: Evidence files persisted in `LocalEvidenceStorageService` are immutable. If an OCR parser encounters a corrupt font stream or parsing timeout, the stored physical evidence file is **never** deleted or marked corrupt.
2. **Reviewer Chain Intact**: Evaluators reviewing the student's submission in the OSAD verification queue have full access to view and download the genuine attached PDF/image file regardless of whether automated OCR extracted zero, partial, or complete text.
