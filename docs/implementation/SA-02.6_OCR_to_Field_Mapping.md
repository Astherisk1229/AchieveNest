# SA-02.6 — OCR / Extraction to Field Mapping

## 1. Document Purpose & Core Invariant

This document establishes the comprehensive field-by-field extraction and pre-fill specification for the AchieveNest Student Award & Portfolio Flow.

### The Inviolable Core Invariant
$$\text{OCR / Extraction Output} = \text{Suggestion / Pre-filled Value}$$
$$\text{OCR / Extraction Output} \neq \text{Verified Data}$$

Under no circumstances does OCR confidence, automated parsing, or document extraction transition an achievement record into a verified state. All extracted fields are treated as suggestions that the student must review, edit if necessary, and explicitly submit. Final verification is reserved exclusively for authorized institutional evaluators.

---

## 2. Field Extraction Classification Definitions

Every submission-related field is assigned exactly one of four extraction classifications:

1. **`OCR_EXTRACTION_SUPPORTED`**: The field value can be extracted directly as free-text, parsed date, or numeric quantity from document text layers or OCR raster scans.
2. **`DROPDOWN_MATCHABLE`**: The field requires selecting a controlled value from SA-02.3. Extracted text patterns are matched to canonical machine keys using deterministic keyword rules. Unmatched text yields `NO_MATCH` (unselected).
3. **`MANUAL_ONLY`**: The field represents student narrative, reflection, or subjective context not present in raw certificate text (e.g. `description`). Must be entered manually.
4. **`NOT_APPLICABLE`**: The field is either an evidence file source object or a system-managed workflow property (`status`, `verified_by`, `score`, `points`, `id`) which is strictly protected against OCR writing.

When a student uploads a single certificate or documentation file, the extraction pipeline processes the document text sequentially to extract all supported fields in a single pass:

## 5. Multiple Evidence Files Policy

When an achievement submission includes multiple attached evidence files:
1. **Primary Extraction File**: The OCR engine runs extraction against the **first eligible uploaded file** (File index 0) to generate initial form pre-fill suggestions.
2. **Subsequent Files**: Uploaded supplementary files are securely attached to the submission bundle in `LocalEvidenceStorageService`.
3. **No Uncontrolled Merging**: The engine does not perform unguided merging or overwriting between multiple files to avoid contradictory data conflicts.
4. **Manual Trigger Available**: The student can explicitly trigger re-scan against a specific attached file if desired.
