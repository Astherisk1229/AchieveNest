# SA-02.6 — Controlled Value Extraction Mapping

## 1. Document Purpose
This document defines the deterministic translation rules between raw text extracted from uploaded evidence documents and the frozen canonical dropdown values established in **SA-02.3 (Controlled Vocabulary Table)**.

---

## 2. Controlled Matching Rules & States

Extraction mapping uses four deterministic matching states:
1. **`EXACT_MATCH`**: Extracted text exactly equals canonical key or canonical label (case-insensitive).
2. **`AUTHORIZED_ALIAS_MATCH`**: Extracted text contains an authorized, explicit textual synonym or regex trigger.
3. **`NO_MATCH`**: Extracted text does not match any authorized alias or keyword. Result is left blank or unselected.
4. **`OTHER_MATCH`**: If no canonical value matches but the field permits `other`, the system may pre-select `other` and suggest companion text if configured.

> **CRITICAL RULE**: Silent or speculative fuzzy guessing (e.g. defaulting unstated scope to `national` or unstated placement to `champion`) is **FORBIDDEN**.

## 4. `Other` Policy Handling During Extraction

When extracted evidence text describes an entity that does not match canonical keywords, but the schema provides an `other` choice with a companion text field:
1. System leaves the dropdown as `NO_MATCH` (unselected) by default so the student can make an explicit selection.
2. If explicit trigger `OTHER:` or `CUSTOM:` appears in structured evidence metadata, system selects `other` and places the descriptive text in `<field>_other`.
3. In all cases, the student can change or clear the pre-filled companion text.
