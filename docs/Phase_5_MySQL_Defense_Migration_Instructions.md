# Non-Negotiable Safety Rules

1. Do not modify, delete, rename, or overwrite `backend/app/Database/Migrations/`.
2. Do not execute PostgreSQL/Supabase migrations against MySQL.
3. Do not execute the new MySQL package against `achievenest_local` until Phase 5A passes.
4. Do not manually create application tables in phpMyAdmin.
5. Do not import a random SQL dump.
6. Do not copy Supabase internal schemas/tables such as:
   - `auth.users`
   - `storage.buckets`
   - `storage.objects`
7. Do not reproduce PostgreSQL RLS in MySQL.
8. Do not use:
   - `auth.uid()`
   - `CREATE POLICY`
   - `ENABLE ROW LEVEL SECURITY`
   - `SECURITY DEFINER`
   - PostgreSQL database roles such as `anon`, `authenticated`, `service_role`
9. Do not store physical evidence files as BLOBs.
10. Do not place evidence files in a public web directory.
11. Do not store:
    - plaintext passwords
    - temporary passwords
    - password hashes in audit logs
    - reset tokens
    - bearer tokens
    - cookies
    - Authorization headers
    - service keys
12. Do not invent stakeholder rules, taxonomy wording, award definitions, or reference rows.
13. Do not create a final `departments` table.
14. Do not reintroduce the Department Secretary role.
15. Do not add Graduate School to the current defense scope.
16. Do not add interview scoring, final-awardee selection, or winner-management tables.
17. Preserve the finalized business model even when the SQL implementation changes.

# Frozen MySQL Representation Rules

Use these implementation rules consistently across the MySQL package.

## IDs

Use:

```sql
CHAR(36)
```

for application UUID-compatible identifiers.

UUID values should be generated by the application later.

Do not use:

```text
uuid
gen_random_uuid()
uuid_generate_v4()
BINARY(16)
```

unless a later approved design explicitly changes the rule.

## JSON

Translate PostgreSQL:

```text
jsonb
```

to:

```sql
JSON
```

## Timestamps

Translate PostgreSQL:

```text
timestamptz
```

to:

```sql
DATETIME(6)
```

Store application timestamps in UTC.

## Numeric values

Translate:

```text
numeric(p,s)
```

to:

```sql
DECIMAL(p,s)
```

## IP addresses

Translate PostgreSQL `inet` to:

```sql
VARCHAR(45)
```

## Boolean values

Use:

```sql
BOOLEAN
```

with MySQL `TINYINT(1)` semantics.

## Business state/type columns

Prefer:

```sql
VARCHAR(...)
CHECK (...)
```

instead of MySQL `ENUM`.

## PostgreSQL arrays

Use `JSON` only when the value is genuinely list/configuration data.

Relationships such as Personnel-to-Programs or Organization-to-Programs must remain normalized through junction tables.
