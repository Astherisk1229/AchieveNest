## 1. Document Purpose

This matrix establishes the definitive handling rules for potential duplicate, overlapping, or repeated portfolio records during the student award evaluation and candidate generation process.

---

## 2. Core Duplicate Handling Principles

1. **Intra-Route Uniqueness:** Within a single award criterion subsection, a physical portfolio record (`portfolio_record_id`) may only be counted **once** (`COUNT_ONCE_PER_RECORD`). Repeated inclusion in an evaluation pass is strictly ignored.
2. **Highest-Only Routes:** For routes governed by `HIGHEST_ONLY`, all matching records for the student are collected into a candidate pool, sorted by point value descending, and only the single highest-scoring record is awarded points (`HIGHEST_ONLY`). All subordinate matching records receive 0 points with the explainability code `LOWER_THAN_HIGHEST`.
3. **Cross-Award Multi-Tenancy:** The same verified portfolio record may qualify and score independently across multiple distinct awards (`ALLOW_ACROSS_AWARDS`). Cross-award score evaluation operates on independent candidate snapshots and does NOT deplete caps across award boundaries.
4. **Lifecycle Exclusions:** Superseded, archived, draft, or rejected portfolio records are ignored by the evaluation pipeline (`IGNORE_SUPERSEDED` / `REJECT_UNVERIFIED`).
