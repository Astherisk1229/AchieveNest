# Personnel Evaluation Track — Plan F — Phase F5: Plan C Integration & Historical Safety

## Integration Boundary: Plan C (Portfolio Submission, Versioning & Locking)

### Plan C Responsibilities:
- Portfolio submission lifecycle (draft, submitted, locked, archived);
- Version lineages and point-in-time snapshots;
- Snapshot locking upon formal submission.

### Verification of Historical Immutability:
- **Rule Version Pinning**: Submitted snapshots preserve the immutable `evaluation_scale_code` and `rule_version` (`NDMU-PERSONNEL-RATING-V2`).
- **No Recalculation Drift**: Plan F evaluates historical snapshots using the exact frozen version stored at submission time. Future configuration changes will not rewrite historical scoring outcomes.
- **Snapshot Integrity**: The finalized result DTO generated by Plan F5 persists into the submission snapshot record without mutating the underlying Plan C version lineage.
