# SA-02.6 — OCR / Extraction Source Audit

## 1. Document Purpose
This audit inspects and inventories the actual extraction stack implemented or planned across AchieveNest for both student achievements and personnel portfolio workflows. It establishes the technical baseline for Phase SA-02.6 (OCR / Extraction Mapping).

---

## 2. Extraction Stack Architecture Overview

The extraction architecture in AchieveNest operates on a strict **Client-Side Text Extraction & AI/Heuristic Entity Parsing** model coupled with a **Backend Secure Evidence Storage and Verification Chain**:

```
[Uploaded Evidence File (PDF/Image/Doc)]
                 │
                 ▼
     [SecurityController.validateFileUpload]
     (MIME, Magic Bytes, File Size <= 10MB)
                 │
                 ▼
     [OcrScanController.extractTextFromFile]
     ├── PDF: Stream / Tj / TJ / BT-ET Token Parser (Native ArrayBuffer)
     ├── Text/Doc: TextDecoder (UTF-8 stream parsing)
     └── Images: Canvas / Tesseract OCR Bridge / Direct text extraction
                 │
                 ▼
     [OcrScanController.classifyCategory]
     (Weighted High/Med/Negative Keyword Matrix Scoring)
                 │
                 ▼
     [OcrScanController.extractFieldsFromText]
     (Deterministic Regex, Cue Parsing, Canonical Vocabulary Matchers)
                 │
                 ▼
     [OcrScanModel.createExtractionResult]
     (Normalized suggestion payload with isSuggestionOnly: true)
                 │
                 ▼
     [Frontend Form Pre-fill Suggestion Layer]
     (Fills form inputs as editable suggestions; records remain unverified)
```

## 3. Audited Extraction Services and Classes

| Component / File | Role & Capabilities | Zero-Fabrication Enforcement | Status |
|---|---|---|---|
| `frontend/src/controllers/OcrScanController.js` | Main extraction orchestrator. Handles file validation, binary/text extraction, category classification, regex date extraction, issuer/title parsing, and controlled vocabulary matching. | **STRICT**. Never guesses missing fields; empty evidence yields blank fields; never defaults date or issuer. | **ACTIVE** |
| `frontend/src/models/OcrScanModel.js` | Defines extraction result schemas, category keyword rules (`CATEGORY_RULES`), field metadata descriptors (`createFieldEntry`), and result factories. | **STRICT**. ## 4. Extraction Engine Capabilities by Document Layer

| Capability | Engine / Parser | Supported Formats | Handling Mechanism |
|---|---|---|---|
| **Embedded PDF Text Layer** | `extractTextFromPdfBuffer` in `OcrScanController.js` | `.pdf` | Decodes ArrayBuffer streams; extracts literal `(text) Tj` tokens, `[(t1) (t2)] TJ` arrays, and `BT...ET` stream blocks. |
| **Plain Text / Document Stream** | `TextDecoder('utf-8')` | `.docx`, `.doc`, `.txt` | Decodes binary/XML text streams and extracts readable character sequences. |
| **Image OCR (Pixel Raster)** | Canvas Image Preprocessing / Tesseract Integration Bridge | `.png`, `.jpg`, `.jpeg` | Inspects binary image buffers and extracts optical characters into plain text lines. |
| **Date Parser** | Deterministic Multi-Pattern Regex | All formats | Extracts ISO (`YYYY-MM-DD`), Month-DD-YYYY, and DD-Month-YYYY; validates calendar validity (days per month, leap years). |
| **Scope / Level Matcher** | Explicit Keyword Matcher | All formats | Identifies exact scope tokens (`INTERNATIONAL`, `REGIONAL`, `NATIONAL`, `IN-HOUSE`) and maps to canonical vocabulary. |
| **Issuer / Organizer Parser** | Header Trigger Regex | All formats | Searches for `ORGANIZED BY:`, `CONFERRED BY:`, `ISSUED BY:`, or official institutional names. |
| **Placement / Result Matcher** | Phrase Token Normalizer | All formats | Normalizes terms like `1ST RUNNER UP` -> `first_runner_up`, `CHAMPION` -> `champion`. |

## 5. Summary of Audit Invariants

1. **Extraction = Suggestion**: All extracted data is structured as non-authoritative suggestions.
2. **Zero Verification by OCR**: The extraction pipeline never transitions an achievement to `verified`.
3. **Editable Fields Only**: Pre-fill suggestions only apply to student-editable form inputs.
4. **Deterministic Vocabulary Matching**: Extracted text must resolve to frozen SA-02.3 canonical values or remain `NO_MATCH`.
