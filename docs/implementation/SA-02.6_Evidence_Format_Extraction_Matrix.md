# SA-02.6 — Evidence Format Extraction Matrix

## 1. Document Purpose
This document maps each supported evidence upload format (finalized in SA-02.5) to its extraction capability, text parser, OCR necessity, and status across the AchieveNest system.

---

## 2. Evidence Format Extraction Matrix

| Format | MIME Type | Upload Supported? (SA-02.5) | Text Extraction? | OCR Needed? | Parser / Service Pipeline | Extraction Capability Status |
|---|---|---|---|---|---|---|
| **PDF** (`.pdf`) | `application/pdf` | **YES** | **YES** | No (for text layer) / Yes (for scanned raster PDFs) | `OcrScanController.extractTextFromPdfBuffer` (Tj/TJ/BT-ET stream parser) + Image OCR bridge | **FULL_EXTRACTION_SUPPORTED** |

## 3. Extraction Protocol Rules by Format

### 3.1 PDF Files (`application/pdf`)
1. **Primary Extraction Route**: Parse binary PDF buffer for literal strings inside `Tj` operators and array elements inside `TJ` operators.
2. **Stream Fallback**: Search for raw text in `BT ... ET` text object blocks.
3. **Scanned PDF Fallback**: If the PDF consists solely of scanned raster images without an embedded text layer:
   - System flags warning: `"PDF does not contain an embedded text layer. Please enter accomplishment details manually."`
   - Image stream is passed to OCR raster engine.
   - Form defaults to manual entry without blocking upload or submission.

### 3.2 Raster Image Files (`image/png`, `image/jpeg`)
1. **Direct OCR Route**: Loaded via `FileReader` as DataURL / ArrayBuffer.
2. **Preprocessing**: Normalized for contrast and DPI where needed.
3. **Extraction**: Optical character recognition parses lines of text, preserving vertical sequence for title, issuer, and date detection.
4. **Failure State**: If image is blurry or contains no recognizable text, system returns `confidence: 0`, leaving form fields blank for student entry.

### 3.3 Word Documents (`.docx`, `.doc`)
1. **Direct Stream Extraction**: Extracts XML text nodes (`w:t` tags) from uncompressed document bodies.
2. **Structured Matching**: Extracted text lines are fed into the standard regex and keyword classifiers.
3. **Legacy Binary DOC**: If `.doc` binary formatting obscures text nodes, the student is notified to verify pre-fill or enter details manually.

---

## 4. Invariant Matrix Rules

- **Zero-Blocking Invariant**: A failure or limitation in text extraction for any format **never** rejects the file upload itself. The file is securely persisted in `LocalEvidenceStorageService`, and the student simply enters details manually.
- **Zero-Fabrication Invariant**: If a format yields low confidence or unreadable text, no default values are manufactured.
