## 1. Audit Objective

This audit inspects all backend controllers, entity models, authorization services, and validators to determine which software layers enforce ownership and write boundaries.

---

## 2. Ownership Enforcement Source Matrix

| Field / Domain | Software Layer & File | Enforcement Mechanism | Security Boundary |
|---|---|---|---|
| `student_profile_id` | `StudentPortfolioController::create()` | Resolved strictly from `$actor['profile_id']` in JWT Authorization header. Request JSON cannot override. | Server-side Identity Binding |
| `status` (Workflow) | `StudentPortfolioController::create()` & `VerificationService` | Hardcoded default `'submitted'` or `'draft'` on create; status mutations require Evaluator role permissions. | Role-Based Authorization Guard |
| `verified_by` / `verified_at` | `student_portfolio_verification_events` table | Written only in evaluator verification transaction with authenticated evaluator profile ID. | Database Transaction Isolation |
| `score` / `points` / `award_id` | `PortfolioStructuredMetadataValidator::FORBIDDEN_METADATA_KEYS` | Explicit rejection in validator: any student payload containing these keys throws an `INVALID_STRUCTURED_METADATA` error. | Whitelist & Blocklist Validation |
| `id` / `record_id` | `StudentPortfolioController::genUuid()` | Auto-generated UUID v4 on record insert; client-supplied primary keys are ignored. | Server-Side UUID Generation |
| `evidence_hash` | `LocalEvidenceStorageService::uploadFile()` | SHA-256 hash computed directly from file buffer upon receipt. | Cryptographic Integrity Layer |

---

## 3. Audit Conclusion

All system-managed and protected workflow fields are enforced on the server-side, preventing client-side spoofing, mass assignment, or privilege escalation.
