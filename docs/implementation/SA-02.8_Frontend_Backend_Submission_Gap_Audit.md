# SA-02.8 — Frontend / Backend Submission Gap Audit

## 1. Document Purpose
This audit analyzes validation parity between frontend React forms (`AchievementSubmissionModal.jsx`, `portfolioFormSchemaRegistry.js`) and backend API validators (`PortfolioStructuredMetadataValidator.php`, `StudentAchievementValidationService.php`).

---

## 2. Validation Parity Matrix

| Validation Rule / Feature | Frontend Enforcement (React) | Backend Enforcement (CodeIgniter 4) | Parity Status | User-Facing Error Message |
|---|---|---|---|---|
| **Base Title Required** | Checked in `validateForm(isSubmitNow)` (`formData.title.trim().length >= 3`). | Enforced in `validateBaseFields` (`required\|min_length[3]`). | **MATCH** | *"Title is required (minimum 3 characters)."* |
| **Organizer Required** | Checked in `validateForm` (`formData.organizer_or_body.trim().length >= 2`). | Enforced in `validateBaseFields` (`required\|min_length[2]`). | **MATCH** | *"Organizer / Issuing Body is required."* |
| **Start Date Required** | Checked in `validateForm` (`!formData.start_date`). | Enforced in `validateBaseFields` (`required\|valid_date`). | **MATCH** | *"Start date is required."* |
| **End Date $\ge$ Start Date** | Checked in `validateForm` (`end_date < start_date`). | Enforced via date comparison rule. | **MATCH** | *"End date cannot be before start date."* |
| **Category & Subcategory Required** | Checked in `validateForm` (`!categoryId \|\| !subcategoryId`). | Enforced via `validateTaxonomyPair`. | **MATCH** | *"Primary Category and Subcategory are required."* |
| **Evidence Attachment Required** | Checked in `validateForm` (`evidenceFiles.length === 0`). | Enforced in submission validation (`evidence.min_count[1]`). | **MATCH** | *"At least one supporting evidence attachment is required before submitting."* |
| **Structured Metadata Requiredness** | Dynamic schema check (`currentSchema.fields.forEach(f.required)`). | Dynamic schema lookup & required field enforcement in `PortfolioStructuredMetadataValidator`. | **MATCH** | *"{Field Label} is required."* |
| **Controlled Vocabulary Whitelist** | Dropdown option restrictions in UI selector. | Strict `in_list` validation against canonical array in `PortfolioStructuredMetadataValidator::CONTROLLED_VOCABULARIES`. | **MATCH** | *"Invalid value selected for {Field Label}."* |
| **Forbidden Key Rejection** | UI never renders inputs for score/points/status. | Backend strips keys matching `FORBIDDEN_METADATA_KEYS`. | **MATCH** | (Silently stripped / blocked) |
| **Draft Submission Flexibility** | Draft action skips required structured checks, enforcing only date range sanity. | Backend endpoint accepts `status: "draft"` with partial metadata. | **MATCH** | *"Draft saved successfully."* |
| **Status Protection** | UI allows selecting `draft` vs `submit_now`; never exposes `verified`. | Backend hardcodes initial state to `draft` or `submitted`. | **MATCH** | *"Achievement submitted for verification."* |

---

## 3. Gap Analysis Summary

- **Total Rules Audited**: 11 core validation rules
- **Mismatches Detected**: 0
- **Validation Parity**: **100% Exact Match**. Frontend client validation provides immediate feedback, while backend server-side validation acts as an impenetrable security boundary against tampered API requests.
