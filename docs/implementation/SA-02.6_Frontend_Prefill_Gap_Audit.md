# SA-02.6 — Frontend Pre-Fill Gap Audit

## 1. Document Purpose
This audit analyzes the current state of frontend pre-fill behavior in React modals (`AchievementSubmissionModal.jsx`, `PersonnelSubmissionModal.jsx`) and components (`EvidenceUploadSection.jsx`) to confirm compliance with SA-02.6 requirements.

---

## 2. Frontend Pre-Fill Lifecycle Audit

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Student Uploads Evidence File                             │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. OcrScanController processes file                          │
│    - Extracts text, dates, issuer, scope, category          │
│    - Returns result with isSuggestionOnly: true             │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. Pre-fill Suggestion Applied                               │
│    - Empty fields: populated with extracted value            │
│    - Existing values: preserved (no silent overwrite)        │
│    - Form inputs remain 100% student-editable               │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. Student Reviews, Edits, and Submits                       │
│    - Record created in 'draft' or 'submitted' status        │
│    - Verification state is NEVER altered by OCR             │
└─────────────────────────────────────────────────────────────┘
```

## 3. Detailed Component State Audit

| Component / Subsystem | Current Behavior | Target SA-02.6 Requirement | Gap / Status |
|---|---|---|---|
| **`AchievementSubmissionModal.jsx`** | Manages form state (`formData`, `structuredMetadata`, `evidenceFiles`). Allows pre-fill on initial load or upload. | Form inputs must be editable suggestions. Status must remain decoupled from OCR results. | **COMPLIANT**. Inputs are fully mutable controlled inputs. |
| **`EvidenceUploadSection.jsx`** | Accepts PDF, JPG, PNG, DOC, DOCX files up to 10MB. | Emits file objects to extraction controller upon upload. | **COMPLIANT**. Accepts all authorized formats and triggers file handling. |
| **`OcrScanController.js`** | Produces structured suggestion payload; flags ambiguous dates; normalizes ISO dates (`YYYY-MM-DD`). | Canonical dropdown matchers must map only to SA-02.3 values. Unmatched cues yield `NO_MATCH`. | **COMPLIANT**. Employs zero-fabrication extraction contract. |
| **Form Lock / Readonly State** | Forms are only locked if status is `submitted` or `verified` (post-submission). | OCR suggestions must never lock an editable form field. | **COMPLIANT**. OCR pre-fill never sets `disabled` or `readOnly` on user inputs. |
| **Verification Indicators** | OCR confidence score is displayed as informational metadata only. | UI must not label an OCR result as "Verified Record" or bypass evaluation. | **COMPLIANT**. UI denotes suggestions as advisory; verification badges are reserved for evaluator approval. |

## 4. Existing Value Preservation Policy

When OCR produces extraction results:
1. **Empty Field Policy**: If the target student-editable field is currently empty, the extracted value is pre-filled directly.
2. **Existing Value Policy (`DO_NOT_OVERWRITE_MANUAL_VALUE`)**: If the student has already entered text or made a manual dropdown selection before OCR completes or reruns, the student's manual input is preserved. The extracted suggestion is made available via an advisory chip or badge without silent replacement.
3. **Editable Guarantee**: The student retains complete authority to overwrite, edit, or clear any pre-filled value prior to submission.
